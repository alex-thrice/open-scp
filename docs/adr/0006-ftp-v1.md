# ADR 0006: границы первой версии FTP

## Контекст

T30 добавляет FTP после завершения общей очереди, безопасного хранения credentials, диалога
повторного ввода пароля и восстановления путей. FTP принципиально отличается от SFTP: обычный
FTP не шифрует управляющее или data-соединение, не подтверждает подлинность сервера и зависит от
нестандартизованного формата команды `LIST` на старых серверах. Нельзя обозначать его иконкой
защищённого соединения или объявлять возможности только потому, что конкретный сервер иногда их
поддерживает.

## Решение

- Первая версия поддерживает только обычный незашифрованный FTP. FTPS, включая explicit и
  implicit TLS, выносится в отдельную задачу: для него нужны отдельные UX состояния сертификата,
  политика TLS и integration matrix. Отключение проверки TLS не добавляется.
- Поддерживается только passive mode. Перенаправление data-соединения на host, отличный от
  control connection, запрещено, чтобы не допускать FTP bounce. Active mode не поддерживается.
- Аутентификация — имя пользователя и пароль. Anonymous FTP возможен только как явно созданный
  профиль с введёнными пользователем username/password; скрытых значений по умолчанию нет.
- `basic-ftp` 6.2.1 находится только в main process. Renderer получает профиль без пароля,
  типизированные состояния и безопасные коды ошибок. Raw FTP replies и stack traces остаются в
  main process и не включаются в пользовательские сообщения или diagnostics.
- Control connection использует UTF-8 и отправляет `OPTS UTF8 ON`. Для листинга библиотека
  сначала использует MLSD, когда сервер объявил MLST, затем документированно откатывается к
  `LIST -a` и `LIST`. При fallback дата изменения не считается достоверной и может отсутствовать.
- Все data-соединения passive. Передачи выполняются потоками через общий Transfer Engine и его
  conflict policy. Пароль хранится только через `CredentialService`/`safeStorage`; отсутствующий
  или неверный пароль обрабатывается общим диалогом T28.
- Первая версия объявляет `read`, `write`, `createDirectory`, `delete`, `rename` и настоящие
  каталоги. Она не объявляет atomic rename, server-side copy, permissions, symbolic links,
  checksum, multipart upload или resume. Перезапись при rename выполняется как явные delete +
  rename и поэтому неатомарна.
- Форма профиля и каждая FTP-панель показывают постоянное предупреждение, что пароль, имена и
  содержимое файлов передаются без шифрования. Для FTP используется отдельная иконка без щита.

## Последствия

FTP подключается к существующим профилям, вкладкам, восстановлению путей, внешнему редактору и
очереди без отдельной модели операций. Без MLSD UI может показывать имя, тип и размер, но не
должен использовать недостоверную дату для проверки изменения. Отмена активной FTP-передачи
закрывает control/data connection; следующий безопасный retry выполняет явное переподключение.

Совместимость зависит от поддержки passive mode и от MLSD, Unix- или DOS-подобного `LIST`.
Неизвестный формат листинга возвращается как типизированная unsupported/io ошибка без raw reply.

## Отклонённые альтернативы

- **Включить FTPS тем же флагом.** Отклонено: это скрыло бы проверку сертификата и различия
  explicit/implicit TLS внутри формы обычного FTP.
- **Включить anonymous credentials автоматически.** Отклонено: неявные credentials усложняют
  аудит и повторный запрос пароля.
- **Объявить resume и atomic rename по наличию команд REST/RNTO.** Отклонено: FEAT не гарантирует
  безопасную семантику конкретного сервера, а T30 запрещает неподтверждённые capabilities.
- **Разрешить active mode или отдельный transfer host.** Отклонено из-за сложности NAT/firewall и
  риска FTP bounce.
