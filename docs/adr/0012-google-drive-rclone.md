# ADR 0012: Google Drive через настроенные remotes rclone

- Дата: 2026-11-16.
- Статус: принято; заменяет решение о прямом Google OAuth/API из ADR 0010.

## Причина

Общий OAuth-клиент OpenSCP получил требование ежегодного платного аудита CASA.
Проект не продолжает этот путь публичной верификации. Для доступа к Google Диску
используется внешний rclone с подключением, которое пользователь настраивает
самостоятельно. Это изменение архитектуры и процесса настройки, а не заявление
об освобождении приложения или пользовательского OAuth-проекта от правил Google.

## Решение

Сохранить отдельный provider kind `google`, но выполнять файловые операции через
rclone. Профиль выбирает remote типа `drive`; iCloud использует `iclouddrive`.
Имена remotes позволяют разделять аккаунты и корни. Они не считаются подтверждённой
личностью пользователя и не заменяют проверку конфигурации при подключении.

Общий запуск процессов и потоковый адаптер переиспользуются с iCloud. Google
использует абсолютные пути относительно remote. Встроенный OAuth-клиент,
Google API transport и хранение Google-токенов в OpenSCP удаляются. Старые профили
требуют выбора remote, credentials удаляются, адреса `gdrive:` сбрасываются.

Использование общего OAuth client ID rclone не является основой интеграции:
[rclone предупреждает о его выводе из эксплуатации в 2026 году](https://rclone.org/drive/#making-your-own-client-id)
и требует собственного клиента. Подготовка remote описана в документации rclone;
OpenSCP предоставляет выбор уже настроенного подключения.

## Последствия и ограничения

Пользователь устанавливает rclone отдельно и управляет его credentials в его
конфигурации. Смена аккаунта выполняется выбором другого remote или изменением
конфигурации rclone, а не кнопкой входа OpenSCP. Удаление профиля не удаляет remote.

Поддерживаются обычные файлы и папки, потоковое чтение/запись, переименование
и корзина. Google Docs и ярлыки скрываются; прежнего экспорта/обратного импорта
native-документов нет. Неоднозначные имена отклоняются. Продолжение с offset
и прямое серверное копирование не объявляются. Реальные аккаунты и платформы
нуждаются в отдельной приёмке.
