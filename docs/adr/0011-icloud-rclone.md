# ADR 0011: iCloud Drive через внешний rclone

Дата: 2026-10-19. Статус: принято для прототипа T34; приёмка реального сервиса открыта.

## Решение

Добавить `ICloudProvider`, реализующий `FileSystemProvider`, с отдельными процессами rclone
для операций. Пользователь устанавливает актуальный rclone и предварительно создаёт
подключение типа `iclouddrive` через `rclone config`. Профиль OpenSCP содержит только имя
этого подключения, начальный каталог и timeout. Для нескольких аккаунтов используются
разные имена подключений. Это прямой доступ через rclone, без системной папки Apple.

Переход к этому варианту согласован запросом владельца реализовать T34 через rclone.
Поддержка rclone не означает наличия официального публичного API всего iCloud Drive:
модуль обращается к веб-сервисам iCloud. Изменения Apple могут нарушать подключение.

## Границы первой версии

- Вход, основной пароль Apple Account, 2FA, обновление cookies/trust token и ADP обслуживает
  rclone. Собственного экрана входа Apple в OpenSCP пока нет.
- Бинарник не включается в дистрибутив и не скачивается приложением. Абсолютный путь
  к файлу или папке с ним можно выбрать в дополнительных настройках приложения.
  Приоритет: сохранённый путь →
  `OPENSCP_RCLONE_PATH` → `rclone` из PATH. Импортируемые профили не могут задавать
  исполняемый файл, аргументы или путь конфигурации. Путь не экспортируется с профилями.
- Используется стандартный конфиг rclone либо `RCLONE_CONFIG`. Конфиг и его секреты остаются
  под управлением rclone; они не копируются в базу OpenSCP, экспорт или диагностику.
  `RCLONE_CONFIG_PASS` поддерживается для заранее зашифрованного конфига. Интерактивный запрос
  пароля конфигурации отключён, чтобы дочерний процесс не зависал без терминала.
- Перед подключением проверяется точное имя и тип remote через `listremotes --long`, затем
  доступность корня через `lsjson --stat`. Для remote принудительно выбирается service=drive.
- При запуске приложения, после изменения пути и по кнопке «Проверить rclone» выполняется
  локальная проверка `version` и `listremotes --long` с общим лимитом 3 секунды, без обращений
  к Apple. Она заполняет `rcloneAvailable` и `icloudRemotes` в snapshot. Работающий rclone
  разрешает создание профиля даже без готовых remotes; переключатели источников исключают
  профили с отсутствующим remote. Статус проверки отображается в настройках.
  Профили в базе и менеджере подключений сохраняются.
  Смена пути запрещена во время активных передач, мутаций или проверки iCloud-соединения.
- `lsjson`, `mkdir`, `moveto`, `rmdir`, `purge`, `deletefile` обслуживают метаданные и мутации.
  `cat` и `rcat` передают содержимое через stdout/stdin с backpressure. Процесс запускается
  без shell и без видимого консольного окна. Количество памяти не зависит от размера файла.
- Унаследованные `RCLONE_*` настройки операций исключаются из окружения дочерних процессов;
  сохраняются только путь конфига и его пароль. Ошибки нормализуются, stderr не попадает
  в IPC, диагностику или сообщения пользователя. Вывод метаданных ограничен 16 МиБ.
- Отмена и disconnect завершают дочерние процессы; metadata timeout ограничивает время
  команды целиком, timeout rclone ограничивает ожидание сетевого ввода/вывода.

## Передачи и конфликты

Общая очередь выполняет копирование с ранее поддержанными источниками. Провайдер не обещает
resume, server-side copy или атомарный rename. Прямой `openWrite` сначала загружает файл
`.openscp-upload-<UUID>` в тот же каталог, проверяет размер и неизменность назначения, затем
публикует `moveto`. При ошибке предпринимается ограниченная по времени очистка; при обрыве
сети или завершении приложения временный файл может остаться в iCloud.

Проверка версии по ID, размеру и времени изменения является best effort. Между последней
проверкой и публикацией возможна гонка с другим клиентом; атомарного compare-and-swap нет.
Нельзя заявлять строгую защиту от конкурентной перезаписи. Неопределённый результат публикации
обрабатывается механизмом проверки общей очереди. Удаление через rclone не обещает корзину.

Каждая операция создаёт процесс, что увеличивает задержку просмотра и число авторизаций.
Переход к постоянно работающему `rcd` стоит рассматривать после проверки реального сервиса.

## Проверка и приёмка

Воспроизводимый CLI fixture проверяет контракт провайдера, изоляцию сессий, отмену, timeout,
сохранность назначения при неудачной записи, метаданные профилей и общую очередь. Локальный
smoke настоящего rclone проверяет совместимость команд без обращения к Apple. Electron-тесты
проверяют скрытие недоступных профилей, настройку пути, сохранение после перезапуска и возврат
профилей при появлении настроенного remote. Эти тесты не подтверждают совместимость с Apple.

До закрытия T34 нужны реальные тесты на Windows/macOS/Linux: вход и повторный вход,
ADP, несколько аккаунтов, CRUD, пустые и большие файлы, Unicode, сетевые сбои, отмена
и обмен с каждым поддерживаемым источником. Условия зависимости T33 остаются в плане.
