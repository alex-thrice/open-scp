# ADR 0008: Единая проверка подключения в редакторе профилей

- Статус: принято по запросу владельца.
- Дата: 2026-10-19.

## Контекст

Кнопка проверки реализована только для Mail.ru в T31. Владелец запросил одинаковую проверку
для SFTP, FTP, S3 и Mail.ru и возврат к списку подключений из редактора Mail.ru.

## Решение

- Заменить частную IPC-команду `test-mailru-profile` общей `test-profile` с ID сохранённого
  профиля. Как и прежняя проверка Mail.ru, кнопка сначала сохраняет настройки и секрет.
- Создавать отдельный провайдер в main, проверять соединение и чтение начального каталога
  или S3 bucket/prefix. Всегда закрывать его в `finally`. Панельные сессии, пути и очередь
  не изменяются; проверка не создаёт удалённых файлов и не обещает наличие права записи.
- Вернуть типизированный результат `connectionTest`: успех либо запрос подтверждения
  неизвестного SSH-ключа с адресом, портом и отпечатком. Секреты в результат не включаются.
- Для SFTP main запоминает предъявленный неизвестный ключ и настройки профиля. Повторная
  команда может передать явно подтверждённый `trustFingerprint`; main принимает его только
  при совпадении с ожидающим подтверждения ключом и неизменным профилем. Ранее доверенный
  изменившийся ключ не заменяется. Повторное соединение снова проверяет реальный ключ.
- Все формы используют общие подписи проверки и общий вывод результата/подтверждения.
  Неверный пароль исправляется в той же форме. SSH agent и ключи используют существующий
  механизм credentials, проверка не вводит отдельного способа хранения секретов.

## Последствия

Редактор остаётся открытым после проверки. Результат сбрасывается при изменении полей.
Кнопки редактирования недоступны во время сохранения/проверки. Сохранённые профили и база
данных не меняют формат; добавляются команда и необязательное поле IPC-результата.
