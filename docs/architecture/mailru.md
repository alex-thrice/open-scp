# Облако Mail.ru

Решение: [ADR 0007](../adr/0007-mailru-webdav.md). Собственный клиент WebDAV использует
`https://webdav.cloud.mail.ru`, email аккаунта и пароль внешнего приложения с правом
«Полный доступ к Облаку». Обычный пароль и пароль VK ID не используются.
Основание — [официальная справка Mail](https://help.mail.ru/cloud/desktop/webdav/), проверенная
2026-10-19. Реальная совместимость с аккаунтом Mail.ru ожидает ручной приёмки.

## Профили, процессы и пути

`MailruConnectionProfile` содержит `kind: mailru`, имя, email, начальный каталог, timeout и
`SecretReference`. Endpoint/TLS-настройки не принимаются из профиля или IPC. Пароль хранится
через `safeStorage`, копия профиля получает отдельный секрет, импорт не содержит credentials.
Существующие профили и таблицы SQLite не меняются.

`MailruConnection` управляет входом, HTTP agent и отменой; `MailruProvider` реализует общий
контракт, `WebDavTransport` выполняет HTTP, `webdav-xml` разбирает DAV multistatus.
Сохранённый пароль, Authorization и протокольный клиент остаются в main process.
Проверка подключения сохраняет профиль и проверяет чтение корня/начального каталога отдельным
кратковременным соединением без создания панельной сессии и изменения удалённых файлов.
Общая команда `test-profile` и результат проверки всех типов описаны в
[ADR 0008](../adr/0008-profile-connection-checks.md).
HTTP 401 даёт `AUTHENTICATION_FAILED`. HTTP 403 при начальной проверке корня даёт
`MAILRU_WEBDAV_ACCESS_DENIED` с подсказкой о пароле приложения и повторным вводом;
это не утверждает, что пароль неверен. После входа HTTP 403 остаётся
`PROVIDER_ACCESS_DENIED` без повторного запроса пароля. Тело отказа в IPC не возвращается.

Абсолютные пути относятся к корню аккаунта; traversal и управляющие символы отклоняются.
Сегменты URL кодируются отдельно, href декодируется один раз и проверяется по origin и
принадлежности каталогу. `%`, `#`, `?`, `+`, `&` и Unicode сохраняют буквальное значение.
`PROPFIND` использует Depth 0/1. XML и служебные ответы ограничены 32 МиБ, DTD/ENTITY запрещены,
ошибки parser не выводятся в логи. Статусы response/propstat проверяются, необязательное
свойство с 404 допускается. Redirect не выполняется, проверка TLS не отключается.

## Возможности и передачи

| Возможность                               | Первая версия  |
| ----------------------------------------- | -------------- |
| Настоящие каталоги, list/stat, mkdir      | Да             |
| Потоковые read/write, rename/move, delete | Да             |
| Атомарность rename и достоверность mtime  | Не объявляются |
| Resume read/write                         | Не объявляется |
| POSIX permissions, симлинки, checksum     | Не объявляются |
| Server-side copy, multipart               | Не объявляются |

Корректная дата показывается при наличии. Только сильный корректный ETag используется как
`versionTag`/`If-Match`; это идентификатор версии, а не MD5/checksum.
Local ↔ Mail.ru и Mail.ru ↔ SFTP/S3/FTP используют общую очередь и ограниченные буферы с
backpressure; между удалёнными источниками нет промежуточного локального файла.

PUT пишет `.openscp-part-…` с известным Content-Length. После ответа сервера проверяются размер
и неизменность источника, затем выполняется MOVE с `Overwrite: F` или явным `Overwrite: T`.
Предварительного DELETE назначения нет. `If-None-Match: *` защищает PUT без перезаписи,
а `Overwrite: F` — публикацию от гонки имени. Обрыв финального MOVE требует проверки результата
пользователем; публикация автоматически не повторяется. Очередь остаётся сессионной.

Отмена прерывает HTTP, но сервис может оставить временный файл. Resume не предлагается;
явный restart общей очереди начинает запись с нуля. DELETE может завершиться частично:
HTTP 207 разбирается и ошибка не скрывается. Проверка пустоты перед нерекурсивным DELETE не
блокирует параллельную запись другим клиентом.
401 вызывает повторный запрос пароля приложения, 403 означает отказ доступа; 507 (квота)
и 429 (частота запросов) имеют отдельные локализованные ошибки. Diagnostics не содержит
сырые ответы, Authorization, email и полные пути.

## Тестовый транспорт

Явное внедрение HTTP endpoint разрешено только на loopback. Для development Electron нужны
одновременно `OPENSCP_WEBDAV_FIXTURE=1` и `OPENSCP_TEST_MAILRU_ENDPOINT=http://127.0.0.1:<port>`;
packaged-приложение игнорирует эти переменные. Формат профиля от fixture не зависит.
Contract/protocol tests используют одноразовый WebDAV fixture; integration проверяет очередь,
32-МиБ roundtrip, конфликты и реальные адаптеры OpenSSH/MinIO/FTP. Electron E2E проверяет форму,
вход, test connection, передачу, шифрование и переподключение после рестарта.
Это не подтверждает тарифные ограничения и особенности настоящего сервиса. Ручной сценарий:
[подключение Mail.ru](../user/mailru.md).
