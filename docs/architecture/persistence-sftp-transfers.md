# Persistence, SFTP и Transfer Engine v1

## T04: данные и секреты

SQLite находится в `app.getPath('userData')/settings.sqlite`. Используется встроенный
`node:sqlite` исключительно в main process, без второго native binding. Миграции выполняются
в транзакции, версия хранится в `user_version`: v1 — profiles/credentials/settings,
v2 — trusted_hosts; добавленная в T13 v3 — multipart_cleanup. Более новая неизвестная версия отклоняется. Включены foreign keys,
cascade deletion credentials и secure_delete.

`ProfileStore` проверяет metadata строгой схемой. Профиль содержит ссылки на credentials,
а не пароль/passphrase/S3 secret. `CredentialService` шифрует значение через Electron
safeStorage, отклоняет недоступный backend и Linux `basic_text`. Некорректный ciphertext
возвращает только локализуемый запрос повторного ввода. При смене секрета старый blob удаляется
в той же транзакции; ссылку на секрет чужого профиля сохранить нельзя.

Поле ввода пароля неконтролируемое: секрет не записывается в React state, очищается в DOM
при отправке и однократно передаётся в main через фиксированный валидируемый запрос.
Main никогда не возвращает секрет в ответе. Приватный ключ выбирается системным file picker
и читается только main process с ограничением 1 МиБ. Необработанные ошибки библиотек и payload
не логируются; для диагностических объектов предусмотрен `redact`.

## T08–T09: SFTP

`ssh2` используется напрямую.
Необязательный модуль `cpu-features` исключён через pnpm, сборка дополнения ssh2 отключена.
Сборка приложения не зависит от C++ toolchain; криптографические операции AES при этом
используют встроенный `node:crypto`.

Конструктор соединения требует хранилище host keys, а каждое
подключение задаёт `hostVerifier`. Fingerprint — SHA-256 исходного server key. Неизвестный ключ
прерывает handshake; UI показывает адрес и fingerprint и требует явного доверия. Сохранённый
ключ не перезаписывается действием trust. Changed key блокируется без кнопки принятия.

Поддерживаются password, private key + optional passphrase, SSH Agent через `SSH_AUTH_SOCK`
или Windows OpenSSH named pipe. Наличие запущенного агента и загруженного ключа — условие
использования agent mode; Pageant, jump hosts и keyboard-interactive не реализованы.

У каждой вкладки собственное соединение. Управляющий и потоковый SFTP-трафик используют
разные каналы одного SSH connection. Для управляющих операций действует отдельный лимит
восемь запросов. Передача файла использует ограниченную очередь: по умолчанию 64 запроса
при загрузке и 32 при скачивании, как в WinSCP. В «Настройки → Передачи» оба значения
можно менять в диапазоне 1–128; значение 1 включает последовательную передачу.
Настройки сохраняются в `transfer-settings-v1`, применяются при открытии следующего
потока и не меняют уже работающие очереди. Отсутствующие или повреждённые настройки
заменяются значениями по умолчанию.
Есть timeout, keepalive и отслеживание потери соединения. Ошибки и состояния передаются в UI
через безопасные snapshot-ответы, без SDK-типов и stack traces. Листинг читает каталог порциями,
закрывает handle, отбрасывает `.`/`..`, сохраняет permissions, timestamps и типы объектов.
Рекурсивное удаление использует lstat и удаляет сам симлинк, не его цель.

## T10: совместимое расширение контрактов

Для требуемого планом resume добавлен необязательный `offset` в `ProviderOperationOptions`.
Старые вызовы продолжают читать/писать с начала. Offset — неотрицательное безопасное целое;
capabilities Local/SFTP объявляют поддержку resume. FakeProvider её не объявляет.

`RenameOptions.overwrite` — дополнительная явно выбранная возможность. По умолчанию
сохраняется отказ при существующем destination. Local использует rename ОС; SFTP для замены
использует OpenSSH atomic rename extension. Если сервер не поддерживает extension, overwrite
не эмулируется удалением оригинала: операция завершается ошибкой, оригинал остаётся на месте.

Добавлен один фиксированный IPC-канал `workspace:request` со строгим discriminated union
допустимых действий. Это не произвольные имена каналов или выполнение команд. Ответы также
валидируются в main и preload. Существующие local/runtime IPC-контракты сохранены.

## Передачи и границы v1

Очередь выполняет одну операцию за раз. Потоки используют чанки до 64 КиБ с backpressure;
UI показывает байты, скорость, elapsed/ETA, cancel, resume и restart. Каталоги передаются
рекурсивно; симлинки и special entries не разыменовываются и отклоняются. Политики конфликтов:
ask (требует решения), overwrite, skip, rename/«сохранить оба» и программный fail.

Прогресс загрузки SFTP учитывает только подтверждённые байты через `WriteOptions.onProgress`
и capability `writeProgress`. Перед закрытием handle, возвратом ошибки или завершением
отмены провайдер дожидается уже отправленных операций. Скачивание сохраняет порядок
блоков при ответах в произвольном порядке и дочитывает короткие ответы сервера.
Буферы ограничены размером очереди, а не размером файла. Проверки целостности,
продолжение и публикация временного файла остаются в TransferEngine.

Файл в обоих направлениях сначала пишется под уникальным `.openscp-part-…`. Только после
закрытия потока и проверки размеров/mtime он переименовывается в финальное имя. Отмена не
публикует неполный файл. Части отменённых/неудачных операций остаются под явным временным
именем для продолжения; их можно удалить как обычные файлы, если продолжение не требуется.

Transient ошибки повторяются не более двух раз после первой попытки. Resume работает только
для той же операции в текущем процессе: проверяет направление/провайдеры, размер, mtime,
размер частичного файла и SHA-256 **всего** сохранённого префикса с bounded streaming. При
расхождении продолжение запрещено, доступен restart с нуля. Стабильные имена частей и выбранных
rename-targets предотвращают незаметные дубликаты при retry.

Персистентное восстановление очереди после перезапуска относится к T14 и не реализовано.
Полный multi-select, drag-and-drop, расширенный менеджер профилей и release signing остаются
за границей T10. Части без восстановленной очереди не продолжаются автоматически.

API-основания: [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage),
[Node SQLite](https://nodejs.org/api/sqlite.html),
[ssh2](https://github.com/mscdex/ssh2) и [SFTP API](https://github.com/mscdex/ssh2/blob/master/SFTP.md).
