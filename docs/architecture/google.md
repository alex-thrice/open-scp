# Google Drive через rclone

Текущее решение: [ADR 0012](../adr/0012-google-drive-rclone.md).
Прежняя прямая интеграция Drive API и общий OAuth-клиент OpenSCP описаны
в [историческом ADR 0010](../adr/0010-google-drive-identity-oauth.md).

Google сохраняет отдельный вид провайдера `google`. Профиль хранит имя настроенного
remote rclone, начальную папку и timeout. Обнаружение проверяет тип backend `drive`;
remotes `iclouddrive` остаются в отдельном списке iCloud. Имя remote — локальный
идентификатор подключения, а не подтверждённый email или постоянный ID аккаунта.
Несколько remotes могут указывать на один аккаунт или на разные корни.

Вход Google, refresh и хранение OAuth-данных выполняет внешний rclone. OpenSCP
не включает Client ID, не обменивает коды Google и не хранит его токены. Сайт
OpenSCP не является OAuth callback. Собственный клиент rclone пользователь
настраивает по [официальной инструкции](https://rclone.org/drive/#making-your-own-client-id).
Переход на rclone не является обещанием освобождения от правил Google.

Пути — обычные абсолютные адреса `/folder/file` относительно корня выбранного
remote. Старые `gdrive:`-адреса с цепочкой ID не используются. При миграции профили
сохраняют имя, но требуют выбора remote; прежние Google credentials удаляются,
а начальные папки и недавние адреса старого формата сбрасываются на `/`.
Импорт и экспорт профилей переносят имя remote, но не конфигурацию и секреты rclone.

Адаптер использует общий механизм запуска rclone с iCloud: фиксированный executable,
аргументы без shell, очистка унаследованных флагов операций, ограниченные потоки,
timeout и отмена дочерних процессов. Google и iCloud сохраняют свои provider kind
в путях, сессиях и нормализованных ошибках. Пользователь задаёт executable через
дополнительные настройки; расширенные параметры описаны
в [настройке rclone](../development/icloud-rclone.md).

Обычные файлы читаются потоками через `cat`. Запись идёт в отдельный временный
объект, проверяется размер и состояние назначения, затем выполняется публикация.
Передачи между провайдерами проходят через компьютер. `resumeRead`, `resumeWrite`
и `serverSideCopy` не объявляются; повтор прерванной передачи начинается с нуля.
Удаление использует корзину Drive (`--drive-use-trash=true`).

Native-документы Google и shortcuts пропускаются флагами `--drive-skip-gdocs`
и `--drive-skip-shortcuts`. Прежние экспорт/обратный импорт Google Docs и выбор
назначения по ID не поддерживаются. Дубли имён объектов и неоднозначные компоненты
пути отклоняются как конфликт; адаптер не выбирает произвольный объект.

Автоматические проверки используют подменный rclone. Работа с настоящим аккаунтом,
квоты, политика организации и ограничения платформ требуют отдельной
[приёмки](../development/google-oauth.md).
